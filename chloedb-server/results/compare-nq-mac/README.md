# Strata and thirteen other engines on a simulated cluster (Mac + kind), NQ 1M

**Mac + kind simulation, shared 4 CPUs.** Measured on 2026-11-02 between
05:34 and 12:40 UTC with
[`deploy/compare/compare.sh`](../../deploy/compare/compare.sh) (method,
budgets and query mapping in
[`deploy/compare/README.md`](../../deploy/compare/README.md)). Every
Kubernetes node is a container in one Docker VM on one laptop, so the
engines, the clients and Kubernetes share the same 4 CPUs; the numbers
compare the engines with each other on equal terms, not what any of them does
on real machines. Everything that went wrong on the way, and how each engine's
reports were produced, is in [NOTES.md](NOTES.md).

| | |
|---|---|
| machine | MacBook Air (Mac14,2), Apple M2 (4 performance + 4 efficiency cores), 24 GB, macOS 26.0.1 (25A362) |
| Docker | Docker Desktop, engine 24.0.5, VM with 4 CPUs and 9,379,880,960 bytes (8.7 GiB), LinuxKit kernel 5.15.49 |
| Kubernetes | kind 0.33.0, Kubernetes 1.37.0 (kubectl 1.37.2): 1 control plane and 3 workers, the cluster of `deploy/kind-test.sh up` |
| data | BEIR NQ: the first 1,000,000 of its 2,681,468 passages, every one of the 4,201 that a test query judges relevant among them (`strata/scripts/prepare_beir_local.py --docs 1000000 --backend st`); BAAI/bge-small-en-v1.5 vectors (384 dimensions, unit length) made with sentence-transformers on the M2's GPU; 3,452 judged test queries; synthetic `year`, `category`, `rating`, `topic` |
| budget | 3 CPUs and 6 GiB per engine (Kubernetes limits). Elasticsearch, OpenSearch and Solr: 2 data nodes of 1.5 CPUs and 3 GiB. Strata: 2 shards of 1 CPU and 2.5 GiB and a coordinator of 1 CPU and 1 GiB. Vespa: `vespa-0` (config server, cluster controller, container) 1 CPU and 2.25 GiB, 2 content nodes of 1 CPU and 1.875 GiB. Meilisearch, Typesense, Manticore, Qdrant, Weaviate, Milvus, ParadeDB, Postgres and Redis: one pod of 3 CPUs and 6 GiB |
| layout | the data pods on the first two workers (one-node engines on the first), the clients (and Strata's coordinator, Vespa's `vespa-0`) on the third; Redpanda (1 CPU, 1 GiB, outside the budgets) beside the clients for the streams |
| queries | 300 of the 3,452 queries, every kind at 1, 4 and 16 clients for 6 s each; writes and streams for Strata, Elasticsearch, OpenSearch, Solr and Vespa only |
| runs | one engine at a time; before each timed step the Mac's 1-minute load average had to drop below 5 (up to 10 min), and below 7 from 06:22 UTC on (OpenSearch and every engine after it) |
| quiet | macOS's `mediaanalysisd` paused (SIGSTOP) from 06:14 UTC and Spotlight kept out of the data and report folders from 06:03 UTC (NOTES.md) |

## Files

- `tables.md`: every table, generated by
  [`deploy/compare/analyze.py`](../../deploy/compare/analyze.py) (load and size,
  latency and throughput at 1, 4 and 16 clients, answers, SQL aggregates,
  agreement with Strata, writes, how soon a write is found, streams, CPU, and
  the notes on unavailable and differing kinds);
- `latency-full.md`: q/s, p50, p90, p95, p99, p99.9, max and mean for every
  engine, kind and client count;
- `summary.json`: the same numbers as `tables.md`;
- `run-*.json.gz`: timings and every answer (`run-solr+sql.json.gz`: Solr's
  sql aggregate run on its own, which `analyze.py` merges into Solr's results);
- `load-*.json`, `disk-*.json(l)`, `build-strata-s*.json`: loads and sizes
  (`load-solr-sqlrerun.json`, `build-strata-s*-stream-shards.json` and
  `build-strata-s*-pre-hnsw-fix.json` are the extra loads and builds NOTES.md
  describes; the tables use the others);
- `writes-*.json`, `stream-*.json`: writes and streams;
- `cpu.jsonl` (and the re-runs' `cpu-*.jsonl`): each pod's cgroup CPU time
  around each step;
- `failures/`: the pods' logs and descriptions saved when a step failed.

## Results

See [tables.md](tables.md). In it: every engine has 1,000,000 documents
loaded and searchable; no timed run had an error; Strata, Elasticsearch,
OpenSearch, Solr, Vespa, Manticore, Weaviate, ParadeDB, Postgres and Redis
answer 300 of 300 SQL aggregates as an exact computation does; and the kinds an
engine has no request for, or answers differently, are listed under the tables.
Vespa's numbers come from content nodes at their memory limit (NOTES.md).
