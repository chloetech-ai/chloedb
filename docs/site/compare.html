Why one engine

One copy of each row, one planner, one structure

No pipelines to keep in step

A row's text, columns, vector and edges are written in one transaction and read from one snapshot. There is no second store to re-index, and no window where the search box and the database disagree.

Filters and rankings planned together

The planner sees the filter, the words, the vector and the graph walk of one statement, with exact counts per segment, so it can run the filter inside the vector search or fuse rankings under the same filter.

The laptop runs the cloud's structure

A shard is a Strata file. The file an app opens in-process, the server in front of it and the cluster on Kubernetes read the same format and answer the same SQL.

A console in the box

Every server serves the command center: the cluster drawn live, flame graphs of any query, a relevance lab and a control center to change the cluster by dragging it. The search engines leave this to a second product run beside them.

Where others are ahead

What Strata does not do as well, yet

A comparison that only lists wins is not one. These are the places to look before choosing Strata.

Elasticsearch and OpenSearch

Years of production at very large scale, an ecosystem around them (dashboards, ingest agents, security, alerting), analyzers for dozens of languages, and log analytics at petabyte scale. In the benchmarks they answer SQL aggregates and typo-tolerant search far faster: 4.86 ms against Strata's 4.3 s on an aggregate at 10M.

Vespa

Proven serving at very large scale, tensor ranking with ONNX models in several phases, and a managed cloud. In the benchmarks it is the fastest on BM25 × recency at 10M, 5.42 ms against Strata's 15.5.

Milvus, Qdrant and Weaviate

Indexes built for billions of vectors (on disk, on GPUs), more quantisation choices, and managed clouds. Strata has no vector index built for collections far larger than memory yet. At the benchmarks' shared settings Qdrant's recall@10 at 10M is 0.941, Strata's 0.795.

SQLite and PostgreSQL

Decades of hardening as general-purpose databases, and in SQLite's case a library that runs everywhere in a few hundred kilobytes. SQLite reads a row by id in 8 µs against Strata's 21 and commits single rows faster, and Postgres answers key lookups in half Strata's time at 10M. Strata loads 1.7–5.9× slower than SQLite when it builds an HNSW graph.

Tantivy

Faster facet counts on small collections (1.1–2.1× on three of four BEIR sets) and faster cold structured filters, where a range in Strata touches more pages.

Strata itself

A young project: English and simple analyzers only, no managed service, no point-in-time recovery between checkpoints yet, one writing process per file, a cluster changed through one coordinator at a time until its map changes go through consensus, and changes to the file format and cluster protocol still reviewed one by one.

Strata

Search engine, database and recommender in one, from a file in your app to a cluster. Apache-2.0.
