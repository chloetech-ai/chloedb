Cluster · 1M passages · DigitalOcean · 3 November 2026

Fourteen engines, 1M passages, machines of their own

Every engine ran at once on its own DigitalOcean machines, with the same data, the same 14 kinds of query and three passes. Engines that shard got two machines; the rest one, with the same CPU limit.

Strata wins by breadth: it runs all 14 kinds, is in the top half on 36 of 45 tests, more than any other engine, and is never last. It is fastest outright on only three tests. At the median, Qdrant, Redis, Milvus, Solr and Typesense are faster on the kinds they specialise in.

Data
1M MS MARCO v2.1 passages, with their Arctic Embed M v1.5 vectors (768 dimensions)
Machines
DigitalOcean sfo2: two 4-vCPU nodes for engines that shard, one 8-vCPU node for the rest
Budget
6.8 CPUs per engine. Strata: 2 shards of 2.9 CPUs, a 1-CPU coordinator
Queries
300 dev queries per kind at 1, 4 and 16 clients; the median of three passes
Quality
Recall@10 against an exact search of the same vectors
Cost
$21.29 at list price

Writes and streams

Searchable in 6 ms, and a stream written once

Strata and Vespa make a write searchable when it returns (5.7 and 9.4 ms); Elasticsearch, OpenSearch and Solr refresh every second. Single inserts are slower on Strata than on the Lucene engines. Updates are faster, because Strata sets one column in place. After a consumer crash, Strata resumes exactly, since offsets commit with the rows; the others write some events twice. None lost any.

Load and size

Shown, not ranked

Strata's shards were built offline from local files, the others over HTTP, so load times do not compare.

Where Strata is behind

Four kinds where it is clearly slower

  • Typo search. This build predates #242, which has since cut a coordinator's median from 112 to 15.8 ms on a Xeon VM.
  • SQL aggregates. 178 ms through a coordinator, where Elasticsearch and OpenSearch took 4 to 6. Not fixed yet.
  • Key lookups. Strata's went through SQL here, not its key API, and the others searched the id field rather than calling get-by-id.
  • BM25 at 16 clients. Two rounds to the shards per query; fixed since, below.
Since this run

BM25 through a coordinator, 51% faster at 16 clients

The coordinator now caches each shard version's term statistics (#245), so a BM25 query takes one round instead of two. Measured before and after in one 4-core container (Xeon), with the same answers; not yet re-run on DigitalOcean.
