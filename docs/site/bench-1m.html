Cluster · 1M passages · DigitalOcean · 3 November 2026

Fourteen engines on machines of their own, at 1M passages

Every engine ran at the same time on DigitalOcean node pools of its own, with the same 1M MS MARCO passages, the same Arctic vectors and the same fourteen kinds of query, three passes in a row. The engines that shard (Strata, Elasticsearch, OpenSearch, Solr and Vespa) got two machines each; the rest one machine with the same CPU limit.

Strata gets there by breadth. It runs all fourteen kinds, finishes in the top half on 36 of the 45 tests, more than any other engine, and is never last. It is fastest outright on only three tests, all at the 99th percentile (facets, filtered vectors and similar items): at the median, Qdrant, Redis, Milvus, Solr and Typesense are faster on the kinds they specialise in.

Data
MS MARCO v2.1 passages, the first 1,000,000 of shard 00, with Snowflake Arctic Embed M v1.5 vectors (768 dimensions) as published
Machines
DigitalOcean sfo2, Kubernetes 1.37. Sharded engines: 2 × m-4vcpu-32gb; one-node engines: 1 × m-8vcpu-64gb; each a c-8 client of its own
Budget
6.8 CPUs per engine as Kubernetes limits. Strata: 2 shards of 2.9 CPUs and 24 GiB, a coordinator of 1 CPU
Queries
300 of 1,000 dev queries; every kind at 1, 4 and 16 clients for 6 s each; three passes, the median of each test
Quality
Recall@10 against an exact search over the same vectors. No nDCG: the judgments cover 113M passages, not this slice
Cost
$21.29 at list price, every node pool counted in whole hours

Overall

Summed places over 45 tests

The same ranking under other rules

Strata stays first with throughput at 16 clients and with gaps under 15% counted as ties. It is not first on only the seven kinds every engine runs, where Milvus and Qdrant are ahead, nor on the average place over only the tests each engine ran, where Milvus leads. Its first place comes from running every kind well, not from winning the kinds everyone runs.

Writes and streams

Writes searchable in milliseconds, and a stream written once

Measured for the five engines that shard. "Searchable after" is from a write's request to the first search that finds it: Strata and Vespa make a write searchable when it returns (5.7 and 9.4 ms), while Elasticsearch, OpenSearch and Solr refresh every second, their default. Single inserts are slower on Strata than on the three Lucene engines. Its updates are faster, but they do less work: Strata sets the one column in place, while the Lucene engines re-index the whole document, because the harness keeps the text and vectors out of their _source. In the crash test the stream's consumer dies after a write and before it commits its offsets. Strata keeps a stream's offsets in the same transaction as its rows, so it resumes exactly where it was; the others resume from the offsets they last committed and write some events twice. None lost any.

Load and size

Shown, not ranked

Strata's two shards were built offline, each on its node from local files, while the others took their documents over HTTP from a loader. The times are not comparable, so the ranking leaves load out.

Where Strata is behind

Four kinds where it is clearly slower

  • Typo-tolerant search. The run used a build from before the faster typo walk and the frequency-aware 'auto', which since cut a coordinator's median typed query from 112 to 15.8 ms on a Xeon VM (under the hood).
  • SQL aggregates through a coordinator. GROUP BY category … HAVING COUNT(*) > 1000 took 178 ms where Elasticsearch and OpenSearch took 4 to 6. Not fixed yet.
  • Key lookups. This run sent Strata's as SQL (WHERE id = :k) through the planner, not to the key API that the 10M run used; the other engines answered a search on the id field, not their own get-by-id APIs.
  • BM25 at 16 clients. Two rounds to the shards per query; see the next section.
Since this run

BM25 through a coordinator, 51% faster at 16 clients

Every BM25 query through a coordinator took two rounds to the shards: one for the collection's term statistics, then the query. Since #245 the coordinator keeps each shard version's statistics and skips the first round while no shard has changed. Measured before and after on one 4-core container (Xeon), with the same answers; a re-run on DigitalOcean is in progress.

Raw data

Every number comes from these files

  • README.md: the setup, every job's machines and CPU check, the images, and all the tables
  • passes.md: each pass, and the median and range of every test
  • rank.md: the ranking as rank.py computes it, which also counts load (Strata 226, Elasticsearch 269, OpenSearch 281)
  • The directory: run-*.json.gz per engine and pass, loads, disks, writes, streams and CPU samples
  • The method: budgets, text analysis, vector settings and every engine's request for each kind
  • BM25 under load: the before and after of #245
