ChloeCtx · long-term memory for Claude Code

Claude Code forgets. ChloeCtx doesn't.

ChloeCtx records every Claude Code session into one ChloeDB file per project. A small model writes down the decisions and rules each turn agreed. The next session starts out knowing them, and each prompt gets the history it needs. Nothing depends on the model remembering to save.

Install it See how it works

Local files outside your repository. No account and no server. Built on ChloeDB. Formerly called Engram.

The problem

Summaries keep the plan and lose the particulars

A long session outgrows any context window. Claude Code then compacts it into a summary of about 15,000 characters. A new session starts with only CLAUDE.md and an index of notes. The session that built ChloeDB ran for 32 hours and wrote 43.7 MB of transcript, and its summaries kept under 0.1% of that text.

What the summary keeps

Built a streaming CSV export for stock counts. Tests pass. Next: the purchase suggestions.

What it drops: exact numbers, error messages and paths, why an approach was rejected, a preference said once, three hours earlier.

Store without being asked

Hooks capture prompts, tool calls and results, errors, answers and summaries. Nothing waits for the model to decide something is worth saving.

Load only when it helps

Injected context costs tokens and attention. A gate decides how much to bring back, and nothing the model can still see is repeated.

Let the model ask precisely

When the model knows it needs history, it gets search, a timeline, SQL and a question tool over the same store.

What happens on its own

Six moments in a session, all automatic

Claude Code calls ChloeCtx's hooks as a session runs. Each one answers in a few milliseconds. Hover a step, or watch them light up in turn.

In a session

A requirement nobody repeated

Months earlier, someone said the school is nut-free. Today's request only asks to enter the school's order. The product catalog lists nuts in the Bakewell slice. To get this right, the agent has to connect a request to what it implies.

ChloeCtx's query engine plans several searches for the request, and a second call picks what matters. On this project's tasks of this kind, the new builds solved 12 to 14 of 16 runs. Claude Code with the whole history in context solved 10, and mem0 solved 1.

When the model asks

Six memory tools over MCP

The briefing and recall happen without the model's help. When the model knows it needs more, it asks.

memory_ask

Answer a question about earlier work

Runs several searches at once and answers from them. It is the tool to use first.

memory_search

One hybrid search

BM25 and vectors over every record, with filters by kind, session, file and time.

memory_timeline

What surrounded a record

Opens the turn around a hit, for example the exact command and output of a previous session.

memory_sql

Read-only SQL

One SELECT over the memory table, with a 2-second deadline and a 1,000-row cap.

memory_remember

Keep a note

A decision, rule or fact, filed under the session that kept it.

memory_forget

Forget a fact

Finds every record that holds it, by its words, and removes them.

 chloectx app

Shared spaces in a cluster

A team's memory in a ChloeDB cluster, as an app of its command center, with Context and Seen before.
Safe by default

Built to never get in the way

Never blocks a prompt

A hook that cannot reach its daemon in time prints nothing and exits 0. A failure is said once in the session, with the fix.

Secrets are redacted

Keys and tokens of known shapes become markers before anything is stored or synced.

Outside text is data

What a web page, issue or MCP tool returned is stored but never injected on its own, so nobody can plant instructions for later sessions.

Your files, your machine

Stores live in ~/.local/share/chloectx, one folder per project, outside the repository. CHLOECTX_DISABLE=1 turns it off for a session.

Install

Three ways in, a minute each

Each one installs ~/.local/bin/chloectx and a 129 MB embedding model. It takes effect in your next Claude Code session.

As a Claude Code plugin · nothing to compile 
claude plugin marketplace add chloetech-ai/chloedb
claude plugin install chloectx@chloedb

Or inside Claude Code: /plugin marketplace add chloetech-ai/chloedb, then /plugin install chloectx@chloedb. It downloads the release's prebuilt binary on its first session.

Every session on this machine 
git clone https://github.com/chloetech-ai/chloedb
cd chloedb && ./install.sh

Merges its hooks into ~/.claude/settings.json, after backing it up, and registers the MCP server. It ends by running chloectx doctor.

One project, to try it 
./install.sh --project /path/to/project

Writes only that project's .claude/settings.local.json and .mcp.json. chloectx uninstall takes it out again and keeps the store.
