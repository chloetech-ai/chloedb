ChloeCtx · your memory, for every model

One memory of you. Any model can read it.

ChloeCtx keeps what you tell AI assistants in one ChloeDB file that you own: every message as it was said, and the facts, preferences, plans and decisions a small model writes down from them. Claude, GPT or a local model can query it, and each question gets the two thousand or so tokens of you it needs instead of your whole history.

Install it Why not a plain file?

It works today in Claude Code and in any MCP client on your machine. Importing your ChatGPT, Claude and Gemini history, and signing in from their apps, come in the next release: where it works. Local files, no account. Built on ChloeDB. Formerly called Engram.

The idea

Your context belongs to you, not to one app

Each assistant now keeps its own memory of you, locked inside its app, and you start again whenever you switch. ChloeCtx keeps one memory, as a file on your machine, and any model you use can ask it. Because it keeps everything and hands out only what a question needs, it stays small to read however long your history grows.

Everything, as you said it

Every message is stored as it was said, with its date, before any model decides what matters. Nothing waits for the assistant to choose to remember.

Notes that keep their sources

A small model writes down facts, preferences, plans and decisions, and marks when a newer one replaces an older one. Each note points back to the conversation it came from.

A small slice per question

A question gets the handful of records that bear on it, found by words and meaning together, under a budget. The model reads about two thousand tokens about you, not 170,000.

Yours to see, share and forget

The inspector shows every record. Forget removes a fact everywhere it appears. A capsule hands one slice of it to another person's agent.

Every model gains from the same store

One context per question, built once, took Haiku from 9% to 84% correct, Sonnet from 8% to 87% and Opus from 9% to 89%. Nothing in the memory is tied to the model that reads it.

79 times fewer tokens

2,134 tokens a question against 168,875 for the whole history. That is 43 times less money with Opus, $0.025 against $1.10, and 89 times less with Haiku, ChloeCtx's own model calls included.

Half the reading time

Opus read and answered in 3.8 seconds against 7.6 with the whole history. Search alone adds milliseconds and scored 80%. The query engine's two small-model calls add about 6.4 seconds, which Claude Code spends in the background.

Why not a plain file?

A file of notes about you forgets what it cut

The simplest memory is a file: an about-me.md, a chat app's saved memories, Claude Code's MEMORY.md. A model rereads it after each few conversations and rewrites it to fit. It is cheap to read, but each rewrite decides what to drop, and what it dropped cannot come back. The other easy answer, pasting your whole history into every question, keeps everything and pays for all of it every time.

What the file dropped

With Opus reading, the plain file answered 3 of 11 questions about what the assistant had said, against ChloeCtx's 11; 2 of 6 about preferences, against 6; and 12 of 25 about dates and order, against 23. A rewrite keeps the gist and loses the particulars.

The same size, twice the answers

The file was about as long as ChloeCtx's context, 2,700 tokens against 2,100. The difference is which 2,000 tokens: the file holds what a model guessed would matter, ChloeCtx what this question needs.

Where it works

In Claude Code and MCP clients today, and in every chat app next

The memory, its search and its notes are the same wherever they are used. What differs is how your conversations get in, and how a model reaches the file.

Works today shipped

Claude Code

Records itself, recalls on its own

Hooks store every prompt, tool call and answer, and bring back what each prompt needs without the model calling a tool. A small model writes down what each turn agreed.

 Any MCP client on your machine

Six memory tools over the same file

chloectx mcp is a standard MCP server, so Claude Desktop, Cursor or any client that runs local MCP servers can ask, search and remember, pointed at any folder's memory.

 Capsules

Hand a slice to another agent

Part of a memory as one file that another agent mounts and queries, read-only, with a short note on what it holds.

 On a ChloeDB cluster

A team's shared spaces

The same memory in a cluster's tables, served as an app of its command center, for people and agents who share it.

New: your memory from every chat app next release

chloectx import

Bring your history

Reads the data exports of ChatGPT, Claude.ai and Gemini (Google Takeout), with their dates and who said what, keeping each message once however often you import.

 chloectx me card

A persona card you edit

A personal memory apart from your projects, with a card of what it knows about you. Every line links to the chats it came from, and you confirm, change or drop it.

 chloectx me serve

Sign in from ChatGPT or Claude.ai

MCP over HTTPS with an OAuth sign-in, usable as a ChatGPT connector, a Claude.ai custom connector or in Claude Code. Its tools are persona, search, fetch, ask and remember, and every call goes to an access log.

 capture

Recorded as you chat

A browser extension for chatgpt.com, claude.ai and gemini.google.com, turned on site by site, and a proxy that records any app built on the OpenAI or Anthropic APIs.

 chloectx me share

Share a part of you

A signed, read-only slice such as "my diet and travel" for someone else's agent, with its own key, an expiry, revocation and a log of every read.

In a session

A requirement nobody repeated

Months earlier, someone said the school is nut-free. Today's request only asks to enter the school's order. The product catalog lists nuts in the Bakewell slice. To get this right, the agent has to connect a request to what it implies.

ChloeCtx's query engine plans several searches for the request, and a second call picks what matters. On this project's tasks of this kind, the new builds solved 12 to 14 of 16 runs. Claude Code with the whole history in context solved 10, and mem0 solved 1.

For any model

Six memory tools over MCP

Any MCP client gets the same tools over your memory. In Claude Code, the briefing and recall also happen without the model asking.

memory_ask

Answer a question about earlier work

Runs several searches at once and answers from them. It is the tool to use first.

memory_search

One hybrid search

BM25 and vectors over every record, with filters by kind, session, file and time.

memory_timeline

What surrounded a record

Opens the turn around a hit, for example the exact command and output of a previous session.

memory_sql

Read-only SQL

One SELECT over the memory table, with a 2-second deadline and a 1,000-row cap.

memory_remember

Keep a note

A decision, rule or fact, filed under the session that kept it.

memory_forget

Forget a fact

Finds every record that holds it, by its words, and removes them.

Shared spaces in a cluster

Safe by default

Built to never get in the way

Never blocks a prompt

A hook that cannot reach its daemon in time prints nothing and exits 0. A failure is said once in the session, with the fix.

Secrets are redacted

Keys and tokens of known shapes become markers before anything is stored or synced.

Outside text is data

What a web page, issue or MCP tool returned is stored but never injected on its own, so nobody can plant instructions for later sessions.

Your files, your machine

Stores live in ~/.local/share/chloectx, one folder per project, outside the repository. CHLOECTX_DISABLE=1 turns it off for a session.

Install

Three ways in, a minute each

Each one installs ~/.local/bin/chloectx and a 129 MB embedding model. It takes effect in your next Claude Code session.

As a Claude Code plugin · nothing to compile 
claude plugin marketplace add chloetech-ai/chloedb
claude plugin install chloectx@chloedb

Or inside Claude Code: /plugin marketplace add chloetech-ai/chloedb, then /plugin install chloectx@chloedb. It downloads the release's prebuilt binary on its first session.

Every session on this machine 
git clone https://github.com/chloetech-ai/chloedb
cd chloedb && ./install.sh

Merges its hooks into ~/.claude/settings.json, after backing it up, and registers the MCP server. It ends by running chloectx doctor.

One project, to try it 
./install.sh --project /path/to/project

Writes only that project's .claude/settings.local.json and .mcp.json. chloectx uninstall takes it out again and keeps the store.
