Does Claude Code do better with it? Measured.

The direct test is Claude Code itself, on work that depends on earlier sessions, with ChloeCtx and with each memory a user could pick instead. Then retrieval on the public memory benchmarks, and the cost of a hook at a million records. Where ChloeCtx falls short is at the bottom.

Claude Code, with and without ChloeCtx

Held-out projects: 100 of 100 against 60

A separate agent that never saw ChloeCtx's code wrote two projects, before ChloeCtx was tested on them: stock keeping for a hardware wholesaler and appointment booking for a physiotherapy practice. Each has a recorded history of three sessions and ten follow-up tasks, each run five times per condition in a fresh session. Both conditions have every normal tool, including files, shell and git history. A task counts as solved only when every remembered requirement holds.

What failed without it

Exactly the facts that were only said: purchase suggestions that did not order up to three times the reorder point, a count sheet not in walking order by bin, tomllib for a client that runs Python 3.8, a day plan wider than the 42-character receipt printer, a wrong cancellation fee, and a calendar feed nobody knew had been tried and dropped.

Significance

A permutation test within tasks, 20,000 shuffles, never reached the observed difference (p < 1/20,001). Fisher's exact test on the pooled counts gives p ≈ 10−14.

What did the work

The 6,000-character briefing reached every run. The model called a memory tool in 9 of 100. Runs with ChloeCtx took fewer steps (6.3 against 7.5, and 7.0 against 9.0) and cost about the same, $0.007 to $0.009 a run.

Cloud container, Haiku, 200 runs, nothing changed after ChloeCtx was frozen. Tasks were written alongside the histories and aim at facts they state, so the 40-point gain is on such tasks, not on work in general. Method and runs

Against no memory

The shipped default solves 196 of 208 runs against 92, p < 10−30. mem0 comes closest of the others, 178 (p = 0.009 against ChloeCtx's search only), and depends on the agent calling its tools.

Against the whole history

As many runs solved or more. The whole history costs $0.016 a run while it is in the prompt cache and $0.075 when it is not, against $0.0087 for ChloeCtx's default.

What memory adds to a run

ChloeCtx's 12,000 characters, about 3,000 tokens, are 2% of what the agent reads in a run. claude-mem's observer spent 146,000 tokens a run in model calls, ChloeCtx's query engine 10,600.

Cloud container, Haiku for the agent and every memory system. The three ChloeCtx lanes of the October code differ by 196 to 201 runs, which is this test's run-to-run noise (p = 0.35 for the widest pair). Method, every lane's runs and the pooled tests

Implied requirements

Where the query engine earns its call

One task asks to enter a school's order that includes Bakewell slices. Months earlier the history said the school is nut-free, and the catalog lists nuts in the slice. The request names neither. The new builds left the slice out, saying why, in 4, 3 and 4 of 4 runs. ChloeCtx's search alone did in none, and Claude Code with the whole history in context in 2.

LongMemEval-S

From 72% to 82% correct answers

All 500 questions, each against its own store of a history of about 115,000 tokens, with Haiku as planner, ranker, reader and judge, using LongMemEval's grading prompts. Adding the query engine's picks to ChloeCtx's recall fixed 61 answers and broke 13 (McNemar's exact test, p = 1 × 10−8). The picks alone beat the recall with a quarter of its characters.

The gain is largest where an answer needs several turns: temporal reasoning 66.9% → 81.1%, multi-session 52.9% → 62.8%. Knowledge updates dipped, 86.1% → 83.3%.

Speed and scale

Milliseconds per hook, a million records deep

Reads never wait

With four clients sending prompts to one daemon at 100,000 records, a prompt's p99 fell from 68 to 92 ms to 27 to 31 ms once reads ran on snapshots beside one writer, and the daemon answered twice as many.

Storing is cheap

A 26-hour working session on this repository became 2,204 records, back-filled from its transcript in 6 seconds.

Quality is what scales worst

Finding one conversation's needle among chat on every subject gets harder: 0.80 in the top 10 at 10,000 records, 0.44 at a million. Filters by session, file, kind and time keep real stores precise.

Where it falls short

What ChloeCtx does not do well yet

  • The gate. It keeps costs down but cannot reliably tell a related record from a relevant one: 59% precision against 42% for always injecting on LongMemEval, and no gain on LoCoMo.
  • Questions that chain two facts. "The citizenship of X's spouse" needs a second round of search from the first picks. FactConsolidation's two-hop questions are at 17% with the query engine and 71% with the whole history in context.
  • Answers that need many records at once. BEAM's summaries, contradiction resolution and multi-session reasoning stay at 12 to 38% with any retrieval, Hindsight's included.
  • Whether the model searches. The briefing reached every run in the A/B, but the model called a memory tool in only 9 of 100. That depends on the model and the prompt.
  • The benchmarks are mostly chats. LongMemEval, LoCoMo, BEAM and MemoryAgentBench test assistant memory over conversations. The coding evidence is six small projects, one long session and a handful of live runs, all with one small model.
  • Redaction is pattern-based. It catches common key and token formats and values assigned to names that say they are secret, not every secret.
