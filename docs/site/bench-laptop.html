Cluster · 1M passages · laptop · 2 November 2026

Fourteen engines on one laptop's cluster

A kind cluster of three workers inside Docker Desktop on a MacBook Air, with 3 CPUs and 6 GiB per engine as Kubernetes limits. Every node shares the laptop's four CPUs, so these numbers compare the engines with each other on equal terms, not what any of them does on real machines. The collection is BEIR NQ, whose judgments let every engine's answers be scored with nDCG@10.

On this smaller budget Strata is fastest outright on 14 of the 45 tests (both hybrids at every measure; filtered vectors, similar items and facets at the median and the 99th percentile; phrase and prefix at the 99th), in the top half on 40 and never last, with an nDCG@10 that ties for first on BM25. It is still behind on typo-tolerant search, SQL aggregates and key lookups. One pass, after a warm-up.

Machine
MacBook Air, Apple M2 (4 performance and 4 efficiency cores), 24 GB, macOS 26.0.1; Docker Desktop VM with 4 CPUs and 8.7 GiB
Cluster
kind 0.33, Kubernetes 1.37: a control plane and 3 workers; data pods on two, clients on the third
Budget
3 CPUs and 6 GiB per engine. Strata: 2 shards of 1 CPU and 2.5 GiB, a coordinator of 1 CPU and 1 GiB
Data
BEIR NQ, the first 1,000,000 of 2.68M passages, with every passage a test query judges relevant; bge-small-en-v1.5 vectors (384 dimensions)
Queries
300 of the 3,452 judged queries; every kind at 1, 4 and 16 clients for 6 s each; one pass
Quality
nDCG@10 from NQ's judgments, and recall@10 against an exact vector search

Quality

The same answers, scored against NQ's judgments

Every engine gets the same text analysis and BM25 parameters, so their BM25 answers should agree, and eight of them do within 0.006 (0.305 to 0.311). Meilisearch and Typesense rank by rules of their own, and Postgres with ts_rank, which has no IDF. Hybrids differ most, since an engine that cannot run RRF or min-max fuses in its own way; on RRF Strata is mid-table, behind Meilisearch's semantic ratio, Postgres and Solr.

Writes and streams

Writes searchable in under 2 ms at the median

The same tests as in the cloud: Strata and Vespa make a write searchable when it returns, while Elasticsearch, OpenSearch and Solr refresh every second. Strata's updates set the one column in place, where the Lucene engines re-index the whole document. Strata keeps a stream's offsets in the same transaction as its rows, so after the consumer crashes it writes no event twice.

Load and size

Shown, not ranked

Strata's shards were built offline from local files; the other engines took their documents over HTTP.

Raw data

Every number comes from these files

  • README.md: the setup, images, builds and all the tables
  • NOTES.md: everything that went wrong on the way, and how each engine's reports were made
  • The directory: the raw reports per engine. Solr's SQL aggregate comes from a re-run with its sql module turned on
  • The method: budgets, text analysis, vector settings and every engine's request for each kind
